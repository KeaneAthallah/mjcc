--------------------------------------------------------------------------------
1.  APA APLIKASI INI
--------------------------------------------------------------------------------
Sebuah dashboard pemantauan (command center) untuk Kabupaten Morowali yang
menggabungkan data 3 sektor ke dalam satu halaman kendali:

  - PENDIDIKAN  (Sekolah SD/SMP/SMA/SMK/MI/MTS/MA/SLB, guru, siswa, sarana)
  - KETERTIBAN  (Polsek, Tipkamtikmas, Poskamling, Pasar, Kelurahan/Desa)
  - KESEHATAN   (Puskesmas, Pustu, Rumah Sakit, Posyandu, dokter/perawat/bidan)

Data disimpan sepenuhnya di database (bukan hardcoded). Dashboard menampilkan
statistik, grafik (Chart.js), dan peta interaktif (Leaflet + marker cluster).

Selain dashboard, aplikasi ini menawarkan:
  - SOS / DARURAT  : permintaan bantuan (kategori medical/fire/police) dengan
      alur status (pending -> acknowledged -> on_the_way -> arrived ->
      resolved), pelacakan posisi petugas, dan peta live peta-web
      (marker sender + petugas + rute OSRM petugas->sender).
  - NOTIFIKASI     : baris notifikasi per-user (disimpan MySQL), dikonsumsi
      aplikasi Android lewat polling, dan daftar notifikasi di UI web/API.
  - PUBLIK DATA INTELLIGENCE CENTER : sinkronisasi otomatis 8 sumber data
      eksternal (Satu Data Morowali, ATS, Dapodik, SP2KP, BPS, IRBI,
      Sitaba/Bencana Terkini, APBD) -> dashboard per sumber + peta choropleth
      Indeks Risiko Bencana; dijalankan terjadwal via command `public-data:sync`.
- REAL MASTER DATA : pengganti placeholder seeder dengan data nyata
       per-entitas (sekolah via Dapodik, puskesmas via Kemkes SISDMK, pasar via
       SP2KP) lewat `public-data:dapodik-import` dan `public-data:master-replace`;
       placeholder tanpa sumber publik dinonaktifkan, lalu bisa dihapus permanen
       via `public-data:master-purge` (sudah dieksekusi, DB kini berisi data
       nyata di semua sektor).
  - WIDGET EKSEKUTIF  : tiap dashboard & halaman sumber kini dibuka dengan
       blok "Insight & Rekomendasi" + serangkaian grafik (bar/donut/pie/map).
       Dashboard Pendidikan menampilkan kartu Anak Tidak Sekolah (ATS) langsung
       di beranda pendidikan (komposisi status, progres verifikasi, pemulihan
       DO per jenjang/tingkat, alasan DO, bubble map per kecamatan, peringkat
       kecamatan, insight). Halaman /data-publik-multi/sumber/{key} untuk
       SATU DATA / DAPODIK / SP2KP / BPS / IRBI / SITABA / APBD / ATS juga
       menampilkan "executive widgets" seragam (banner, KPI, insight,
       grafik tambahan) yang dihitung per sumber di controller.
  - REST API `/api/v1`  : autentikasi Sanctum (login/register/verify email)
       untuk memakai semua data + alur SOS dari aplikasi mobile.

4.  DATA & MODEL
--------------------------------------------------------------------------------
Model utama dan relasinya (semua memakai SoftDeletes kecuali User/Subject):

  User            : name, email, password, role (admin/operator/viewer),
                    responder_type (medical/fire/police, nullable)
  SosAlert        : user_id (sender), category (medical/fire/police), message,
                    latitude/longitude/accuracy, status (pending/acknowledged/
                    on_the_way/arrived/resolved/cancelled), responded_by/at,
                    accepted_by/at, resolved_by/at + relasi user/respondedBy
  ResponderLocation: sos_alert_id, user_id (petugas), lat/long, accuracy;
                    riwayat posisi live petugas per SOS (terbaru per user)
  Notification    : user_id, title, body, type ('sos'), data (array JSON,
                    berisi sos_alert_id + category), read_at
  Kecamatan       : name, code, deskripsi, lat/long, is_active
      hasMany -> Kelurahan, School, Polsek, Tipkamtikmas, Poskamling,
                 Market, HealthFacility
  Kelurahan       : belongsTo Kecamatan; population, status
  School          : belongsTo Kecamatan + Kelurahan; belongsToMany Subject
      (pivot school_subject); school_type SD/SMP/SMA/SMK/MI/MTS/MA/SLB
      (School::SCHOOL_TYPES), npsn, lat/long, kondisi, jumlah siswa
      (male/female), guru, kelas, kapasitas, persentase sarana
      (perpustakaan, lab IPA, lab komputer, ruang guru, toilet, tempat ibadah)
  Subject         : nama mata pelajaran
  Polsek          : name, personnel_count, poskamling_count, lat/long, status
  Tipkamtikmas    : title, status, lat/long (belongs to kecamatan + kelurahan)
  Poskamling      : name, is_active, lat/long
  Market (Pasar)  : name, status, lat/long
  HealthFacility  : TYPE_PUSKESMAS/PUSTU/RS/POSYANDU; beds, doctors, nurses,
                    midwives, status, phone, deskripsi

Catatan: koordinat lat/long tersimpan deterministik dari seeder (bukan acak
per-render), sehingga peta konsisten antar halaman.

Kolom `source` pada data master (schools, health_facilities, polseks,
poskamlings, tipkamtikmas, markets) menandai asal tiap baris:
  - 'dapodik' (sekolah), 'kemkes' (puskesmas), 'sp2kp' (pasar): data nyata
    dari pipeline real-master-data.
  - 'manual' (polsek): entitas resmi yang dipertahankan, diisi/dirawat manual.
  - 'seed' (placeholder seeder lama): dinonaktifkan oleh master-replace
    (is_active=false / status='tidak aktif'); dihapus permanen via
    `public-data:master-purge` (purge terakhir: 280 kesehatan, 26 pasar,
    235 poskamling, 152 tipkamtikmas, 170 sekolah).
  - NULL (baris dibuat via CRUD): TIDAK pernah dinonaktifkan otomatis.
Dari hasil penggantian: 216 sekolah Dapodik aktif (155 SD, 41 SMP, 9 SMA,
10 SMK, 1 SLB), 11 puskesmas Kemkes aktif (kecamatan + alamat diisi dari
pemetaan terkurasi, lihat bagian 7.2),
1 pasar SP2KP aktif (Pasar Rakyat Bungku Tengah, kec Bungku Tengah +
koordinat), 4 polsek manual aktif. Posyandu/pustu/RS/poskamling/tipkamtikmas
placeholder sudah dihapus dan menunggu input manual via CRUD di tiap dashboard.

Wilayah kerja hanya Kabupaten Morowali (10 kecamatan: Bahodopi, Bumi Raya,
Bungku Barat, Pesisir, Selatan, Tengah, Timur, Menui Kepulauan, Sombori
Kepulauan, Wita Ponda; 46 kelurahan). Data Morowali Utara (Lembo, Lembo Raya,
Mori Utara/Selatan, Petasia, Petasia Timur) dibersihkan permanen dari DB via
`public-data:master-region-cleanup`, dan impor/pipeline menolak kecamatan
di luar daftar config `public_data.morowali.kecamatan`.

Model Public Data Intelligence Center:
  PublicDataSource : registri sumber data eksternal (key, name, category,
                    description, source_url, adapter_class, enabled, status,
                    record_count, last_sync_at, last_success_at, last_error,
                    sync_duration_ms, config JSON). Di-seed dari
                    SourceRegistry::SOURCES lewat DatabaseSeeder.
                    8 sumber: satudata, ats, dapodik, sp2kp, bps, irbi,
                    sitaba, apbd. Status: pending/success/failed.
  ExternalData     : data generik per indikator (sector, source_key, dataset,
                    topic, year, location, indicator, value, unit,
                    dedupe_key unik) - dipakai ATS & Dapodik.
                    Indikator ATS: 'Anak Tidak Sekolah', '<wilayah> - DO',
                    '<wilayah> - Verifikasi Sudah/Belum' (dataset 'Verval ATS',
                    unit 'Anak'). Indikator Dapodik: 'Jumlah Sekolah',
                    'Jumlah Siswa', 'Jumlah Guru' (lokasi = kecamatan atau
                    'Kabupaten Morowali').
  BpsDataset       : metadata dataset BPS (nama, sumber, kategori).
  BpsObservation   : observasi statistik BPS (dataset_id, region, periode,
                    tahun, nilai, satuan).
  CommodityPrice   : harga kebutuhan pokok SP2KP (commodity, variant,
                    market, price, unit, quantity, percentage_change,
                    record_date - unik per pasar+variant+tanggal).
  DisasterEvent    : kejadian bencana terkini Sitaba (disaster_type, name,
                    location, district, province, event_date, latitude,
                    longitude, sumber).
  DisasterRiskIndex: indeks risiko bencana IRBI (region_name, region_code
                    seperti '72.06', hazard_type, risk_index, risk_level
                    Rendah/Sedang/Tinggi, year, dedupe_key; lat/long nullable).
  ApbdRecord       : data TKDD APBD (year, category, indicator, budget_value,
                    realization_value).

Catatan: koordinat lat/long tersimpan deterministik dari seeder (bukan acak
per-render), sehingga peta konsisten antar halaman.

5.  OTOMATISASI HAK AKSES (ROLE)
--------------------------------------------------------------------------------
Tiga role, dimusatkan di `app/Support/Access.php` dan model `User`:

  - ADMIN    : akses penuh, termasuk kelola pengguna (users) dan kecamatan.
  - OPERATOR : boleh menulis data operasional (sekolah, polsek, pasar, dll)
               TAPI tidak boleh kelola users dan tidak boleh menulis kecamatan.
  - VIEWER   : read-only (hanya melihat dashboard & data).

Untuk modul SOS, pengguna ber-peran OPERATOR dapat diberi `responder_type`
(medical/fire/police) menandai mereka sebagai petugas darurat. Saat SOS baru
dibuat, NotificationService.notifyRelevantResponders() membuat notifikasi
hanya untuk responder yang responder_type-nya cocok dengan kategori SOS
(pengecualian: pembuat SOS tidak dinotifikasi). Otorisasi status SOS
ditangani SosAlertPolicy (mis. hanya sender/petugas kategori cocok yang bisa
merespon).

Lapisan penerapan (berlapis/defense-in-depth):
  1. POLICY   : App\Policies\*Policy. BaseDataPolicy memanggil
                Access::canWrite(resource). Kecamatan masuk ADMIN_ONLY.
                BaseDataPolicy juga menyediakan `restore` (sama dengan canWrite)
                dan `forceDelete` (HANYA admin) untuk fitur sampah.
  2. CONTROLLER: $this->authorize(...) pada index/create/store/show/edit/
                update/destroy (trait AuthorizesRequests di base Controller).
  3. FORM REQUEST: authorize() pada tiap Store/Update Request memanggil
                user->can('create'/'update', ...).
  4. VIEW     : @canwrite('resource') menyembunyikan tombol Tambah/Edit/Hapus.

Blade directive `@canwrite` didaftarkan di AppServiceProvider:
  Blade::if('canwrite', fn ($r) => Access::canWrite(auth()->user(), $r));
  (Default `@canwrite('kelurahan')` = operator BOLEH tulis;
   `@canwrite('kecamatan')` = hanya admin.)

Perlindungan tambahan pada login:
  - Rate limiting login (5 percobaan/menit per kombinasi email+IP) lewat
    RateLimiter::for('login') di AppServiceProvider + middleware
    'throttle:login' pada POST /login.

Peta Gabungan (MapService::combined) memuat SEMUA layer data master + data
publik dalam satu payload `{markers, kecamatans, riskMap}`:
  Master  : school, polsek, kelurahan, market (pasar), poskamling,
            tipkamtikmas, health_facility — hanya baris ber-lat/lng.
  Publik  :
    - external_data      : SatuData/ATS/Dapodik — 1 marker per
                           (kecamatan × sektor), popup jumlah dataset & rekor.
    - disaster_event     : kejadian bencana SITABA (sektor kebencanaan).
    - bps_observation    : ringkasan statistik BPS di centroid Kabupaten.
    - apbd_record        : ringkasan anggaran APBD di centroid Kabupaten.
    - komoditas SP2KP    : dirangkum ke marker pasar (jumlah varian terbaru,
                           komoditas naik/turun tertinggi, tanggal update).
    - IRBI               : bukan marker; overlay choropleth dari payload
                           `riskMap` (region_code -> {name, index, level,
                           hazard} tahun terbaru, indeks tertinggi per kab),
                           dirender di frontend saat sektor Kebencanaan
                           dipilih (fetch public/geo/sulteng-kabupaten.geojson
                           + createRiskChoropleth dengan options.map).
  Sektor map: pendidikan, ketertiban, kesehatan, KEBENCANAAN, STATISTIK.
  Tiap marker publik menyertakan sourceUrl (sumber asli) & detailUrl (halaman
  Public Data). Endpoint /maps/data mendukung ?kecamatan= & ?refresh=1
  (cache 60s).

Resource tambahan tiap resource ber-SoftDeletes (Sekolah, Faskes, Kecamatan,
Kelurahan, Pasar, Poskamling, Tipkamtikmas):
  GET    {resource}/trash           -> daftar data terhapus (sampah)
  PUT    {resource}/{id}/restore    -> pulihkan (perlu izin restore)
  DELETE {resource}/{id}/force      -> hapus permanen (HANYA admin)

Route modul SOS (web):

Menggabungkan 8 sumber data publik ke database secara otomatis, tersiklus

  3. dapodik   : Data Pokok Pendidikan (dapo.kemendikdasmen.go.id), region

  6. irbi      : Indeks Risiko Bencana Indonesia (inarisk.bnpb.go.id).

7.2  REAL MASTER DATA (PENGGANTI DATA DUMMY SEEDER)
--------------------------------------------------------------------------------
Seeder lama mengisi tabel master (schools, kesehatan, ketertiban) dengan data
sintetis sebagai placeholder. Pipeline berikut mengganti (atau mematikan)
placeholder dengan data nyata per-entitas dari sumber resmi yang dapat
dijangkau, tanpa mengubah semantik dashboard:

  1. SEKOLAH  -> Dapodik (dapo.kemendikdasmen.go.id). Endpoint per-sekolah
     ditolak WAF (SafeLine) oleh klien HTTP biasa, sehingga snapshot diambil
     lewat browser asli (playwright-core + MS Edge, headless) oleh
     `scripts/dapodik/dapodik-capture.cjs` -> morowali-schools.json.
     Command `public-data:dapodik-import {file} {--replace}` memetakan baris
     ke tabel schools (NPSN sebagai kunci pencocokan; fallback nama bila NPSN
     kosong). Seluruh jenjang Dapodik dasar & menengah diimpor: SD, SMP, SMA,
     SMK, SLB (TK/PAUD di Dapodik PAUD, madrasah MI/MTs/MA di EMIS Kemenag;
     keduanya di luar cakupan). `--replace` menonaktifkan placeholder aktif di
     jenjang mana pun yang tidak ada di snapshot. Bawahnya, sumber resmi lain
     (referensi.data.kemdikbud.go.id dkk) tidak resolve DNS di lingkungan ini.

  2. PUSKESMAS -> Kemkes SISDMK (dreams.kemkes.go.id), halaman
     /user/kekosongan_dev/SKMPKM/prov/72/kab/7206 (HTTP polos, tanpa WAF):
     tabel per-puskesmas berisi nama, jenis (rawat inap/non), dan isi SDM
     (Dokter/Dokter Gigi/Perawat/Bidan; angka "eksisting/target" -> ambil
     eksisting). Map ke HealthFacility type=Puskesmas, doctors/nurses/midwives,
     condition='baik'. Kecamatan & alamat TIDAK ada di snapshot Kemkes, sehingga
     diisi dari pemetaan terkurasi per-puskesmas di MasterDataImport
     (PUSKESMAS_LOCATIONS), diverifikasi dari sumber resmi (morowalikab.go.id,
     BPJS Faskes, berita Dinkes) sejak 2026-09:
     Ulunambo->Menui Kepulauan, Kaleroang->Bungku Selatan, Lafeu->Bungku
     Pesisir, Bahodopi->Bahodopi, Bahomotefe->Bungku Tengah, Bungku->Bungku
     Tengah, Wosu->Bungku Barat, Bahonsuai->Bumi Raya, La'antula Jaya->Wita
     Ponda, Tanjung Harapan->Menui Kepulauan, Fonuasingko->Bungku Tengah.

  3. PASAR -> SP2KP `master/api/pasar` (kode_provinsi=72, kode_kab_kota=7206):
     hanya 1 pasar nyata di Morowali (Pasar Rakyat Bungku Tengah, id 606)
     lengkap dengan kode kecamatan (7206051 -> Bungku Tengah via kolom `code`)
     dan koordinat lat/lon.

  Alur eksekusi (dua langkah, mengikuti pola Dapodik agar scheduled run tidak
  perlu koneksi hidup):
    - `public-data:master-capture`  : tarik Kemkes + SP2KP -> snapshot JSON
      (storage/app/data/morowali/kemkes-puskesmas.json & sp2kp-markets.json).
    - `public-data:master-replace`  : baca snapshot -> impor puskesmas & pasar;
      MENANDAI untuk pertama-kali baris lama source=NULL sebagai 'seed';
      menonaktifkan semua baris 'seed' yang tersisa (health, market,
      poskamling, tipkamtikmas); polsek ditandai 'manual' dan TETAP aktif.
      Baris source=NULL yang dibuat sesudahnya (via CRUD) tidak pernah disentuh.

  Semua URL bisa override via config/public_data.php (blok `kemkes`, `master`)
  / .env (PUBLIC_DATA_KEMKES_*, dst). Harga SP2KP tetap mengalir terpisah ke
  tabel commodity_prices (Sp2kpAdapter); tabel markets hanya memuat entitas
  pasar (kini 1, nyata).

  Catatan lapangan:
    - Hanya sumber yang dapat dijangkau dari lingkungan yang dipakai;
      yankes.kemkes.go.id / data.kemkes.go.id / dapo.kemdikbud.go.id tidak
      resolve DNS, data.go.id mengembalikan 403. Entitas tanpa sumber publik
      (posyandu/pustu/RS/poskamling/tipkamtikmas) sengaja DINONAKTIFKAN (oleh
      master-replace), bukan dihapus, agar dashboard jujur menampilkan nol.
      `public-data:master-purge` lalu menghapus permanen seluruh placeholder
      ('seed') setelah dipastikan tidak dibutuhkan; baris CRUD (source NULL)
      tidak pernah ikut terhapus.
    - Skor Command Center memakai denominator seluruh baris (termsuk nonaktif);
      setelah penggantian, sektor kesehatan/ketertiban turun secara jujur.

    - mengambil user saat ini via request->user() ?? Auth::user()

  Log login/logout : di App\Http\Controllers\Auth\AuthController
  Halaman /audit   : ActivityLogController + ActivityLogPolicy (admin only),
                     link sidebar "Log Aktivitas" pada layout app.

  PENTING (bug yang pernah terjadi): akses event statis `static::restored()`
  pada model TANPA SoftDeletes (mis. User) memicu rekursi boot Eloquent
  ("may not be called ... while it is being booted"). Solusi: hanya daftarkan
  listener restored/forceDeleted bila model memakai trait SoftDeletes.

-------------------------------------------------------------------------------
12. FITUR SAMPAH (TRASH) & HAPUS PERMANEN
-------------------------------------------------------------------------------
Semua resource ber-SoftDeletes mendukung pemulihan data terhapus:

  Dengan trait App\Http\Controllers\Concerns\HandlesSoftDeletes, tiap controller
  ber-SoftDeletes menambahkan aksi:
    - trash()       -> GET    {resource}/trash (daftar onlyTrashed)
    - restore()     -> PUT    {resource}/{id}/restore (pulihkan)
    - forceDestroy()-> DELETE {resource}/{id}/force (hapus permanen)

  Controller mendeklarasikan konfigurasi `$softDeleteResource`:
    ['class'=>.., 'route'=>.., 'label'=>.., 'searchColumn'=>..]

  Otorisasi (BaseDataPolicy):
    - restore    : sama dengan canWrite => operator boleh memulihkan.
    - forceDelete: hanya admin (User::isAdmin()).

  Halaman bersama: resources/views/trash/index.blade.php
  Tombol "Sampah" ditambahkan di index tiap resource.
