I. TUJUAN & LINGKUP
--------------------------------------------------------------------------------
Cetak biru (blueprint) untuk membangun aplikasi Flutter (mobile & tablet)
yang TAMPILAN dan DATANYA SERUPA dengan website MJCC.

  * HANYA target mobile & tablet (bukan desktop wide-screen).
  * UI berbahasa Indonesia.
  * Semua data diambil real-time dari API Laravel yang SUDAH ADA (Bagian III).
  * Penampilan mengikuti website: warna, bahasa, komponen, chart, peta.

--------------------------------------------------------------------------------
II. TARGET PLATFORM & BREAKPOINT
--------------------------------------------------------------------------------
  * Smartphone : iOS + Android, portrait (utama) + landscape.
  * Tablet     : iPad + Android, portrait + landscape.
  * Breakpoint (mengikuti Tailwind web):
      - mobile : < 768px  -> satu layar, sidebar sebagai drawer off-canvas
      - tablet : >= 768px -> sidebar tetap terlihat (seperti web desktop)
  * Safe area: patuhi MediaQuery padding top/bottom (notch, home indicator).
  * Tinggi konten responsif; ikuti aturan di Bagian XIV.

III. SUMBER DATA - API LARAVEL
--------------------------------------------------------------------------------
Base URL  : {APP_URL}/api  (nilai dari .env app web; produksi pakai domain
            resmi, contoh dev: https://<host>/api).
Semua respons memakai ENVELOPE TERPADU (App\Http\Responses\ApiResponse):

  sukses   : { "success": true, "message": "...", "data": ... }
  list     : { "success": true, "message": "...", "data": [ ... ],
               "meta": { current_page, last_page, per_page, total } }
  error    : { "success": false, "message": "...", "errors": {...} }
               (errors null bila tidak ada)
  validasi : HTTP 422 + errors per-field seperti di atas.

Auth: Laravel Sanctum bearer token. Kirim header:
      Authorization: Bearer <token>
Endpoint publik TIDAK butuh token; lainnya butuh token (auth:sanctum).

DAFTAR ENDPOINT (dari routes/api.php; sinkronkan saat implementasi):

  A. AUTH (publik, throttle)
     POST /api/v1/register
     POST /api/v1/login
     POST /api/v1/email/verify
     POST /api/v1/email/verification/resend

  B. SESSION (token)
     GET  /api/v1/me
     POST /api/v1/logout

  C. DASHBOARD (token) - semua menerima ?kecamatan_id= opsional
     GET /api/v1/dashboard            -> overview (KPI + chart + tabel)
     GET /api/v1/dashboard/education  -> sektor PENDIDIKAN
     GET /api/v1/dashboard/security   -> sektor KETERTIBAN
     GET /api/v1/dashboard/health     -> sektor KESEHATAN

  D. PETA (token)
     GET /api/v1/maps?sector=&type=&kecamatan_id=
       -> { "markers":[...], "kecamatans":[{id,name}] }
       marker: { id, type, sector, name, latitude, longitude, status,
                 kecamatan, kelurahan }
       type marker: school, polsek, tipkamtikmas, poskamling, market,
                    health_facility
       filter: sector = pendidikan|ketertiban|kesehatan; type di atas.

  E. DATA PUBLIK (TERBUKA, tanpa token)
     GET /api/v1/public/overview
     GET /api/v1/public/schools(/{id})
     GET /api/v1/public/health-facilities(/{id})
     GET /api/v1/public/polseks(/{id})
     GET /api/v1/public/poskamlings(/{id})
     GET /api/v1/public/tipkamtikmas(/{id})
     GET /api/v1/public/markets(/{id})
     GET /api/v1/public/kelurahans(/{id})

  F. DATA PUBLIK MULTI-SUMBER (TERBUKA)
     GET /api/v1/public-data/categories         -> daftar kategori
     GET /api/v1/public-data/sources            -> daftar sumber (BPS, APBD, dll)
     GET /api/v1/public-data/sources/{source}   -> isi/indikator per sumber

  G. SOS / DARURAT (token)
     POST /api/v1/sos                             -> buat SOS
     GET  /api/v1/sos                             -> inbox (berizin) / milik sendiri
     GET  /api/v1/sos/my-open                     -> SOS saya yang masih terbuka
     GET  /api/v1/sos/active-count                -> jumlah SOS aktif
     GET  /api/v1/sos/active-incidents            -> insiden aktif (untuk peta)
     GET  /api/v1/sos/{sos}                       -> detail
     POST /api/v1/sos/{sos}/acknowledge           -> petugas menerima (pesan wajib)
     POST /api/v1/sos/{sos}/accept                -> petugas ambil alih
     POST /api/v1/sos/{sos}/on-the-way            -> menuju lokasi
     POST /api/v1/sos/{sos}/arrived               -> tiba di lokasi
     POST /api/v1/sos/{sos}/respond               -> jawab + pesan (menuju lokasi)
     POST /api/v1/sos/{sos}/resolve               -> selesaikan + pesan
     POST /api/v1/sos/{sos}/cancel                -> batalkan (oleh pemilik)
     POST /api/v1/sos/{sos}/location              -> perbarui lokasi pelapor
     GET  /api/v1/sos/{sos}/responder-locations   -> posisi petugas (real-time)

     Field buat SOS (StoreSosAlertRequest):
       latitude (wajib), longitude (wajib), accuracy (0-1000, opsional),
       category (general|medical|fire|police, opsional),
       message   (max 500, opsional)

  H. NOTIFIKASI (token)
     GET  /api/v1/notifications
     POST /api/v1/notifications/{notification}/read

  I. MASTER DATA / CRUD (token) - pola RESTful standar:
     list+search, store, show, update, destroy, trash, restore, force.
        /api/v1/kecamatans        (+trash /{id}/restore /{id}/force
                                     /{kecamatan}/kelurahans)
        /api/v1/kelurahans        (+trash/restore/force)
        /api/v1/subjects
        /api/v1/schools           (+trash/restore/force)
        /api/v1/polseks
        /api/v1/tipkamtikmas      (+trash/restore/force)
        /api/v1/poskamlings       (+trash/restore/force)
        /api/v1/markets           (+trash/restore/force)
        /api/v1/health/facilities (+trash/restore/force)
     Pendukung web (opsional): GET /api/kelurahans/by-kecamatan

  J. USERS, AUDIT, PROFILE (token; users & audit khusus admin)
     GET/POST/PUT/DELETE /api/v1/users + POST /api/v1/users/{user}/verify-email
     GET  /api/v1/audit
     GET  /api/v1/profile
     PUT  /api/v1/profile
     PUT  /api/v1/profile/password

VI. KOMPONEN UI DASAR
--------------------------------------------------------------------------------
1. STAT_CARD (kartu KPI) - dipakai semua dashboard sektor:
     ikon/emoji pemisah warna, label, nilai utama (angka besar), dan baris
     penunjuk (trend/sub). Warna ikon per sektor:
       Pendidikan #2563eb | Ketertiban #7c3aed | Kesehatan #10b981
2. KPI_GRID         - kisi kartu statistik (mobile 2 kolom, tablet 3-4 kolom).
3. KARTU_KONTEN     - wadah putih: header (ikon kecil + judul tebal) + konten.
4. METRIC_COMPARISON- kartu 3 metrik berlabel (mis. jumlah anak, jumlah
                       sekolah, rasio guru:siswa) dalam 3 kolom.
5. CHART_CARD       - kartu berisi judul + chart (Bagian VII).
6. FILTER_BAR       - baris chip/dropdown filter (kecamatan, jenis).
                       Di mobile full-width & bisa scroll horizontal.
7. TABEL            - scroll horizontal di dalam kartu; jangan potong kolom.
8. PAGE_TITLE       - judul halaman + aksi (Tambah, Refresh, Export).
9. BADGE_STATUS     - pil berwarna; hijau (#d1fae5/#047857) untuk
                       Aktif/Ver/Rendah/Resolved; amber/biru untuk
                       Sedang/Diterima/berjalan; merah untuk Tinggi/Tidak
                       aktif/Canceled (lihat tabel status SOS Bagian XII).
10. TREND_INDICATOR - panah naik/turun + angka "vs periode lalu".
11. EMPTY_STATE     - teks "Belum ada data" abu-abu.
12. ERROR_STATE     - pesan + tombol "Coba Lagi" (retry).
13. PAGINATION      - kontrol halaman (pakai meta dari envelope API).
14. TOMBOL          - primer #047857/putih, sekunder outline abu, danger
                       merah; FAB untuk SOS.
15. INPUT/SELECT    - border ringan; di mobile PASTIKAN font >=16px
                       (cara iOS tidak auto-zoom saat fokus).
16. SIDEBAR_MENU    - item ikon+label; submenu expandable (Master Data).
17. SWIPE_REFRESH   - pull-to-refresh pada halaman data/dashboard.
18. SKELETON/SHIMMER saat loading awal (nice-to-have).

  Isi polygon per kecamatan berdasarkan level:
    Tinggi #dc2626 | Sedang #f59e0b | Rendah #10b981 | tanpa data #e5e7eb
    border #334155 bobot 1, fillOpacity 0.7 (kosong 0.65, dash 3-4).
  Legenda kotak kecil; popup nama + badge level + bahaya (opsional).
  Sumber: field `riskMap` pada endpoint /maps (level per kecamatan).

IX.6 INTERAKSI:
  - Reset tampilan (zoom ke seluruh area) saat filter berubah.
  - Filter: sector + type + kecamatan (dari /api/v1/maps).
  - Rute opsional warna #2563eb.
  - SETELAH ROTASI/RESIZE: refresh ukuran peta (di Flutter cukup
    LayoutBuilder + pertahankan koordinat tengah; jangan peta blank).

IX.7 INGAT BUG WEB:
  Di web, z-index Leaflet (hingga 700) bocor keluar wadah dan sempat
  menutupi sidebar; diperbaiki dengan isolation:isolate. Di Flutter
  jangan render peta melampaui wadah Stack-nya; drawer/overlay harus
  berada paling atas.

XII. ALUR SOS & STATUS (polling 15-20 dtk)
--------------------------------------------------------------------------------
STATUS (urutan timeline web):
  active -> acknowledged -> responding -> accepted -> on_the_way
       -> arrived -> resolved      (atau canceled oleh pemilik)

  UI per status:
    active/pending -> merah "Active" (paling atas)
    acknowledged   -> amber "Diterima (pesan)"
    responding     -> "Sedang menuju" (biru/teal)
    accepted       -> ungu/biru "Diambil petugas"
    on_the_way     -> biru
    arrived        -> hijau teal "Tiba di lokasi"
    resolved       -> hijau "Selesai" (tampilkan waktu)
    canceled       -> abu-abu/merah

  AKSI (muncul sesuai state & role):
    acknowledge : petugas tulis pesan (wajib) -> responding
    respond     : petugas tulis pesan -> "menuju lokasi"
    accept      : petugas ambil alih
    on-the-way / arrived : majukan status
    resolve     : petugas selesaikan + pesan
    cancel      : pemilik SOS membatalkan

  LOKASI REAL-TIME:
    - Pelapor : POST /sos/{sos}/location saat GPS berubah
                (latitude, longitude, accuracy).
    - Petugas : GET /sos/{sos}/responder-locations (posisi petugas
                di peta, polling 15-20 dtk).

  Field SOS (SosAlertResource) yang dipakai UI:
    id, user{id,name,role}, latitude, longitude, accuracy, status,
    category, category_label, message, response_message,
    responded_by(+_user{id,name}), responded_at,
    resolved_by(+_user), resolved_at,
    accepted_by(+_user), accepted_at,
    created_at, updated_at, is_owner, can_manage.
